# План разработки Interview Loom

## Цель MVP

Создать демонстрационное веб-приложение для записи тренировочного интервью в браузере, безопасной загрузки записи, последующей расшифровки и AI-анализа. На первом этапе анализ речи и видео не выполняется.

## Этап 1. Базовый работающий MVP

- создать структуру FastAPI-проекта;
- добавить типизированную конфигурацию из переменных окружения;
- подключить SQLite и модель `InterviewRecording`;
- реализовать главную страницу и страницу записи;
- собирать название интервью, должность, вопрос и описание вакансии;
- поддержать режимы «камера и микрофон», «экран и микрофон», «экран, камера и микрофон»;
- записывать медиапотоки через `MediaRecorder`;
- добавить таймер, паузу и продолжение записи;
- показывать предварительный просмотр;
- загружать видео с проверкой MIME-типа и максимального размера;
- показывать страницу результата по публичному идентификатору;
- добавить health-check;
- определить строгую Pydantic-схему согласованного JSON-ответа Gemini и безопасную границу интеграции;
- добавить базовые pytest-тесты, документацию и служебные файлы;
- локально запустить приложение и тесты, затем исправить найденные ошибки.

## Этап 2. Транскрибация — выполнен

- подключить `faster-whisper`;
- декодировать медиаконтейнер через PyAV, поставляемый с FFmpeg-библиотеками;
- выполнять транскрибацию через FastAPI `BackgroundTasks` вне загрузочного HTTP-обработчика;
- сохранять текст и статусы обработки;
- добавить polling, индикатор прогресса и повторный запуск;
- восстанавливать прерванные состояния после перезапуска;
- добавить тесты успешной обработки и ошибок.

## Этап 3. Gemini-анализ — выполнен

- подключить Gemini через отдельный сервис;
- отправлять только подготовленный текст, вопрос, должность и описание вакансии;
- валидировать структурированный ответ моделью Pydantic;
- добавить повторные попытки, таймауты и безопасную обработку ошибок;
- во всех тестах использовать mock вместо реального API.
- полностью переработать интерфейс в адаптивный AI SaaS-стиль;
- добавить onboarding, skeleton loading, карточки оценок и улучшенного ответа;
- сохранять транскрипцию при отсутствии ключа или ошибке Gemini.

## Этап 4. Надёжность и развитие

### Landing и macOS-версия — выполнено

- добавить на главную страницу блок desktop-приложения и CTA скачивания;
- реализовать безопасный endpoint скачивания готовой сборки;
- запускать FastAPI в нативном окне macOS через pywebview/WKWebView;
- хранить пользовательские данные вне `.app` в Application Support;
- собирать автономный Apple Silicon `.app` и переносимый ZIP;
- документировать локальную настройку Gemini и ограничения неподписанной сборки.

### Следующие задачи

- вынести длительную обработку в очередь задач;
- добавить миграции базы данных;
- реализовать удаление и срок хранения записей;
- добавить авторизацию, метрики и расширенные интеграционные тесты;
- подготовить контейнеризацию и production-конфигурацию.

## Production roadmap

Подробный аудит и обоснование архитектуры находятся в `PRODUCTION_AUDIT.md`.

### P0. Baseline и защита существующего поведения — выполнено

- проанализировать backend, frontend, AI-сервисы и desktop prototype;
- зафиксировать текущий результат: 22 теста проходят;
- сохранить FastAPI и существующую Python-бизнес-логику;
- выбрать схему «публичный landing + локальное desktop-приложение».

### P1. Готовые видео и настройки пользователя — выполнено

- добавить file picker и drag-and-drop без удаления MediaRecorder;
- реализовать preview, определение длительности и повторный выбор файла;
- усилить серверную проверку медиаконтейнера;
- добавить desktop settings API и русскоязычный экран настроек;
- хранить Gemini key через системный keyring;
- добавить проверку ключа без сохранения секрета в логах или ответах API;
- покрыть новые сценарии pytest-тестами.

### P2. Общий desktop runtime для macOS и Windows — выполнено

- заменить macOS-only пути на `platformdirs`;
- добавить Windows pywebview backend и корректное завершение локального Uvicorn;
- реализовать single-instance lock и пользовательский экран startup error;
- добавить иконки, единый номер версии и сведения об издателе;
- проверить миграцию существующей локальной базы.

### P3. Воспроизводимые installers — выполнено в коде и CI

- добавить PyInstaller spec и hooks для faster-whisper/PyAV/Google SDK;
- собирать macOS и Windows только на соответствующих ОС;
- создать DMG и Windows installer через нативные CI runners;
- добавить smoke-тест установленного приложения;
- генерировать SHA-256 checksums;
- не включать модели Whisper и пользовательские данные в installer.

### P4. Публичный landing и постоянная ссылка — выполнено в коде и CI

- отделить статическую landing-часть от локальных данных пользователя;
- настроить GitHub Pages и постоянный HTTPS URL;
- подключить custom domain после выбора и покупки домена;
- вести кнопки скачивания на GitHub Release assets;
- добавить privacy policy, support и release notes.

### P5. CI/CD и подписанные релизы — выполнено в коде, подпись требует сертификатов владельца

- GitHub Actions: pytest, compile-check, dependency check и desktop build matrix;
- Apple Developer ID signing и notarization через CI secrets;
- Windows signing или публикация через Microsoft Store;
- автоматическая публикация GitHub Release по version tag;
- ручное подтверждение production release и отсутствие автоматического merge.

### P6. Production hardening — базовая часть выполнена

- добавить Alembic и резервное копирование локальной базы перед миграциями — выполнено;
- заменить Starlette-deprecated test client — выполнено через `httpx2`;
- добавить E2E-тесты записи и загрузки;
- добавить opt-in crash reporting без видео, транскрипций и секретов;
- документировать обновление, откат и восстановление данных.

## Зависимости этапов 1–3

Основные:

- `fastapi` — HTTP API и серверные маршруты;
- `uvicorn[standard]` — ASGI-сервер;
- `sqlalchemy` — типизированная работа с SQLite;
- `pydantic-settings` — конфигурация из окружения;
- `jinja2` — серверные HTML-шаблоны;
- `python-multipart` — загрузка видео через multipart/form-data.
- `faster-whisper` — локальная транскрибация через CTranslate2 и PyAV.
- `google-genai` — официальный Python SDK для структурированного Gemini-анализа.

Для разработки и тестирования:

- `pytest` — тестовый фреймворк;
- `httpx2` — актуальный тестовый HTTP-клиент Starlette/FastAPI.

## Ограничения текущего MVP

- только локальная SQLite;
- видео хранится на локальном диске;
- нет пользователей и авторизации;
- нет отдельной production-очереди задач;
- поддерживаются только явно разрешённые видеоформаты;
- один процесс приложения, без распределённого хранения.
- без `GEMINI_API_KEY` приложение работает в режиме локальной транскрибации.
